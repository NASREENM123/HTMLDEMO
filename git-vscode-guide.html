Step-by-Step Guide

Initial Setup

Install Git & connect it to VS Code

1
Install Git on your computer
+

Download and install Git before anything else. VS Code will detect it automatically.

  • Go to git-scm.com and download for your OS (Windows/Mac/Linux)
  • Run the installer — keep all default options
  • Verify in terminal: type git --version
Terminal — verify install
git --version # Output: git version 2.44.0
2
Configure your identity
+

Git tags every commit with your name and email. Set this once globally.

Terminal
git config --global user.name "Your Name" git config --global user.email "you@example.com"
In VS Code: open terminal with Ctrl+` (Windows/Linux) or Cmd+` (Mac) and run the commands above.
3
Initialize a Git repo in VS Code
+

Turn any folder into a Git repository.

Terminal — inside your project folder
git init
In VS Code: open the Source Control panel (left sidebar icon or Ctrl+Shift+G) → click "Initialize Repository".
📦

Add & Commit

Stage your changes and save snapshots

1
Check what's changed — git status
+

Always check what files are modified before staging.

git status
Source Control panel shows all changed files automatically — red = untracked, orange = modified.
2
Stage files — git add
+

Staging tells Git which changes to include in the next commit.

Stage a specific file
git add filename.txt
Stage ALL changed files
git add .
In Source Control panel: hover a file → click the + icon to stage it. Or click + next to "Changes" to stage all.
3
Commit — git commit
+

A commit saves a permanent snapshot of your staged changes.

Commit with a message
git commit -m "Your commit message"
Stage + commit in one step (tracked files only)
git commit -am "Your message"
In Source Control panel: type your message in the box at the top → click the ✓ Commit button (or press Ctrl+Enter).
4
View commit history — git log
+
Pretty one-line log
git log --oneline --graph
Install the GitLens extension in VS Code for a beautiful visual history in the sidebar.
🌐

Push & Pull

Sync your code with a remote repository (GitHub/GitLab)

1
Connect a remote repository
+

Link your local repo to a GitHub/GitLab remote. Do this once per project.

Add remote named "origin"
git remote add origin https://github.com/user/repo.git
Verify it's connected
git remote -v
In VS Code Source Control panel: click the ··· menu → Remote → Add Remote → paste your GitHub URL.
2
Push changes — git push
+

Upload your local commits to GitHub.

First push (sets upstream)
git push -u origin main
All future pushes (after upstream is set)
git push
In VS Code: click Sync Changes button in the Source Control panel (bottom status bar also shows ↑ push icon).
3
Pull changes — git pull
+

Download the latest commits from the remote to your local machine.

git pull
Pull from a specific branch
git pull origin main
In VS Code: Source Control panel → ··· menu → Pull. Or click the ↓ arrow in the bottom status bar.
Always pull before you start working to avoid merge conflicts with teammates.
4
Fetch (without merging) — git fetch
+

Download remote changes but don't merge them yet — good for previewing what changed.

git fetch origin
🌿

Branch & Merge

Work on features in isolation, then combine them

1
Create a new branch
+

Always create a new branch for each feature or bug fix — never commit directly to main.

Create and switch to new branch in one step
git checkout -b feature/my-feature
List all branches
git branch
In VS Code: click the branch name in the bottom-left status bar → "Create new branch" → type a name.
2
Switch between branches — git checkout
+
git checkout main
In VS Code: click the branch name in the bottom-left status bar → select a branch from the list.
3
Merge a branch — git merge
+

Bring changes from one branch into another. First switch to the target branch (e.g. main), then merge.

Switch to main, then merge feature branch
git checkout main git merge feature/my-feature
In VS Code: Source Control → ··· → Branch → Merge Branch → pick the branch to merge in.
If there are conflicts, VS Code shows them inline with Accept Current / Accept Incoming / Accept Both options. Resolve all conflicts, then commit.
4
Delete a branch (after merging)
+
Delete local branch
git branch -d feature/my-feature
Delete remote branch
git push origin --delete feature/my-feature
🔀

Rebase

Rewrite commit history for a cleaner project log

1
What is rebase?
+

Rebase moves your branch's commits to the tip of another branch, creating a straight linear history instead of a messy merge commit. Think of it as "replaying" your work on top of the latest main.

Never rebase branches that others are working on. Only rebase your own local/feature branches.
2
Rebase your feature branch onto main
+

This updates your feature branch with the latest commits from main.

While on your feature branch
# Switch to your feature branch first git checkout feature/my-feature # Rebase onto latest main git rebase main
In VS Code: Source Control → ··· → Branch → Rebase Branch → select main.
3
Resolve rebase conflicts
+

If conflicts occur during rebase, VS Code highlights them. Fix them, then continue.

After fixing conflicts in VS Code
git add conflicted-file.txt git rebase --continue
Abort and go back to before rebase
git rebase --abort
4
Interactive rebase — clean up commits
+

Squash multiple commits into one, edit messages, or reorder before pushing.

Interactively edit the last 3 commits
git rebase -i HEAD~3
  • In the editor that opens, change pick to squash to combine commits
  • Change to reword to edit a commit message
  • Save and close the file to apply

Clone & Fork

Copy repositories to work on them locally

1
Clone a repository — git clone
+

Downloads a full copy of a remote repository to your computer.

Clone via HTTPS
git clone https://github.com/user/repo.git
Clone into a specific folder name
git clone https://github.com/user/repo.git my-folder
In VS Code: press Ctrl+Shift+P → type "Git: Clone" → paste the repo URL → choose a folder. VS Code will open it automatically.
2
Fork a repository (on GitHub)
+

Forking makes your own copy of someone else's repo on GitHub, so you can make changes without affecting the original. Forking is done on the GitHub website, not in the terminal.

  • Go to the repository on github.com
  • Click the Fork button (top-right of the page)
  • Choose your account as the destination
  • Then clone YOUR fork locally: git clone https://github.com/YOUR-NAME/repo.git
After forking, add the original repo as "upstream" so you can sync updates from it: git remote add upstream https://github.com/original/repo.git
3
Sync your fork with the original
+

Keep your fork up to date with the original project's latest changes.

Fetch and merge from upstream
git fetch upstream git checkout main git merge upstream/main git push # update your fork on GitHub
👥

Collaborate

Work with teammates — pull requests & live share

1
Add a collaborator (on GitHub)
+

Give another person push access to your repository.

  • Go to your repo on github.com
  • Click Settings → Collaborators
  • Click "Add people" → enter their GitHub username or email
  • They'll receive an invitation email to accept
2
Create a Pull Request (PR)
+

A PR lets you propose changes and have teammates review them before merging into main.

  • Push your feature branch: git push origin feature/my-feature
  • Go to the repo on github.com — you'll see a "Compare & pull request" banner
  • Click it, add a title and description, then click "Create pull request"
  • Teammates can review, comment, and approve
Install the GitHub Pull Requests VS Code extension to create and review PRs without leaving the editor.
3
Real-time collaboration — VS Code Live Share
+

Code together in real-time like a Google Doc — your teammate sees and edits your code live.

  • Install the Live Share extension in VS Code
  • Click Live Share in the bottom status bar → Start Collaboration Session
  • A link is copied to your clipboard — share it with your teammate
  • They click the link and join directly in their VS Code (or browser)
4
Resolve merge conflicts with a teammate
+

When two people edit the same line, Git can't decide which to keep.

  • After a conflicted pull/merge, VS Code shows conflict markers inline
  • Click "Accept Current Change" (your code), "Accept Incoming" (their code), or "Accept Both"
  • After resolving all conflicts: git add . then git commit
VS Code's built-in 3-way merge editor (Open in Merge Editor button) makes conflict resolution much easier visually.
🔑

Add Account & Connect Repo

Link GitHub to VS Code and push your first project

1
Sign into GitHub in VS Code
+

VS Code has built-in GitHub authentication — no tokens needed.

  • Click the person icon in the bottom-left corner of VS Code
  • Click "Sign in with GitHub"
  • A browser window opens — log into GitHub and click Authorize
  • Return to VS Code — you're now signed in
Alternatively: open Source Control panel → click "Publish to GitHub" and it will prompt you to sign in automatically.
2
Create a new GitHub repo and push your project
+

The easiest way to start — VS Code creates the GitHub repo for you.

  • Open your project folder in VS Code
  • Open Source Control panel (Ctrl+Shift+G)
  • Click "Initialize Repository" → then "Publish Branch"
  • VS Code asks: public or private repo — choose one
  • It creates the repo on GitHub and pushes all your code automatically!
3
Connect existing local project to existing GitHub repo
+

Already have both? Link them manually.

Full workflow in terminal
# 1. Initialize repo (if not already done) git init # 2. Stage all files git add . # 3. Make first commit git commit -m "Initial commit" # 4. Rename branch to main (optional) git branch -M main # 5. Connect to GitHub remote git remote add origin https://github.com/YOU/REPO.git # 6. Push and set upstream git push -u origin main
4
Set up SSH key (avoid typing password every time)
+

SSH lets you push/pull without entering your password each time.

Generate SSH key
ssh-keygen -t ed25519 -C "you@example.com" # Press Enter for all prompts
Copy your public key
# Mac/Linux cat ~/.ssh/id_ed25519.pub # Windows type %USERPROFILE%\.ssh\id_ed25519.pub
  • Go to github.com → Settings → SSH Keys → New SSH Key
  • Paste the key and save
  • Change your remote URL to SSH: git remote set-url origin git@github.com:user/repo.git
